## 决定了什么，为什么

### 1. 命名收敛（反复漂移后钉死）
- 进度轨 = Growth（经验值，只涨不减，喂等级/quest/collection/未来精灵）。
- 货币轨 = Seeds（可赚可花）。
- 退役了早先的 "Nature XP" 和 "Root XP"。"Root/扎根"意象保留给叙事（如入门 quest "Plant Your Roots"），不再做积分名。
- 约定：owner 说 XP/Root XP = 指 Growth；说 points/nature points/tree points/货币 = 指 Seeds。
- 为什么：Growth/Seeds 讲同一个自然隐喻，比机械的 XP 更贴"会生长的地图"世界观。

### 2. 双轨经济提前进 V1.0（扩大了原定范围 — owner 明确拍板）
- 原倾向是"V1.0 只用一种 XP、不碰真钱"。本 session owner 主动扩大：V1.0 地基同时含 Growth + Seeds 双经济。
- Seeds 核心原则（钉死，视为产品第一原则）：Seeds 不能用钱直接买。只能靠"真实世界做好事"赚。钱可以在花对地方时"奖励"Seeds，但钱不直接变 Seeds。Seeds = proof of real-world participation, not proof of wallet。
- 为什么重要：它让 Seeds 无法被富人用钱刷出来，永远代表"对真实世界做了多少好事"，与 North Star 完美咬合。

### 3. V1.0 真正激活的经济闭环（收窄，其余做叙事态 + schema 预留）
- 赚 Seeds（V1.0 激活）：注册送 + referral + 健康生活方式行为（走路/骑车类）。运动验证/防作弊只做基础或留接口，不现在解。
- 花 Seeds（V1.0 激活）：领养一个 adoptable（扣 Seeds）。
- 其余（本地商家兑换商城、真钱 donation、农场交易）→ schema 预留、逻辑 V2。
- owner 澄清：他贴的商家清单只是示例，V1.0 不接任何本地商家。

### 4. 领养对象泛化 Tree → Adoptable
- trees 泛化成 adoptables（type = tree / crop / animal），共用同一条领养漏斗和"农民按 plot 发更新扇出"机制。
- Apple Tree = hero experience；crop/animal 在 V1.0 只是 schema exercise，不做成复杂体验。

### 5. 真钱交易 = 选项 A（表预留、Stripe 逻辑待线下就绪再接）
- schema 现在把 donations/payments/rewards/redemptions 关系一次定对；Stripe 结算逻辑等 owner 签下农场 + 开通收款后再接。
- 为什么不选现在实装：owner 尚未签农场、未开通收款，现在做真钱逻辑是空转，且会把 Step 1 从"一周地基"变成"支付合规大工程"。

### 6. 采纳 ChatGPT 的 schema 专业意见（第一轮）
全盘采纳：profiles（扩展 auth.users，不另建 User 表）· farm_members（一农场多农民 + role）· Tree 用 UUID 主键、#1048 只是 identifier 字段 · adoptions 加 type/status · plot_updates 改名 + author_id · media 独立成表（farm_media / plot_update_media，多图+视频，非单 photo 字段）· adoptions.display_name（用户给树起的私人名，与 tree identity 分离）。叠加 owner 已定的双 ledger + referral 表。

### 7. 采纳 ChatGPT 第二轮意见中"真正影响代码的两处"，其余归类为文档
- 真改动 Step 1 的只有两处：(a) 新增 impact_events 预留表（真实世界成果账，Impact≠Seeds，Seeds 是游戏货币、Impact 是现实结果，二者不混）；(b) My World 从"首页"升级为"个人现实世界仪表盘/关系地图"。
- 其余（母循环、四层架构、farmer two-sided platform 战略、creature 情感层定位）= 纯文档，不改 CC 今晚做的事。
- 元判断：ChatGPT 擅长把已对的东西重新表述得漂亮，owner 需警惕把"重新表述"误当"新工作"而无限打磨 spec 迟迟不开工。spec 已够开工，两处小改后即停止迭代。

### 8. 形态级决定：改为原生 app（React Native + Expo）
- owner 目标"先做手机 app 增加用户量"，明确选真原生 app。技术栈从 Next.js PWA → React Native + Expo（iOS + Android 一套代码）。
- 后端零改动（Supabase + Resend 全保留）；变的只是前端框架。
- owner 有 Mac，用 Expo Go / iOS 模拟器预览。上架（Apple $99/yr、Google $25）日后线下步骤，不阻塞 Step 1。
- 为什么合理：产品有精灵/计步/拍照/推送需求，原生比 PWA 更适配；桌面精灵 PWA 根本做不到。

### 9. Companion Creatures = V2+，Step 1 只预留 schema
- 精灵：可收集、纯 Growth 喂养、只能通过现实行为（去农场）或 collection/quest 获得、不能买、能对话（接 LLM）、能放桌面。
- owner 确认：Step 1 预留 creatures / user_creatures 两表关系，不做任何精灵交互逻辑。
- 定位钉死：Real world = core, Game = motivation, Creature = emotional attachment。对话（AI 层）+ 桌面形态都是 V2+。
