## 一、My World 视觉方向(源自 owner 认可的参考渲染图)

**风格一句话:** 梦境感的温柔 3D 拟真 + 手绘插画混搭——"你的真树,站在一个诗意的
淡色梦境世界里"。不是扁平 UI,不是纯插画。

**五个风格支柱:**
1. **超现实宁静背景**:柔和蓝天白云 + 起伏的白色地形(雪/云海/晒白沙丘感)。是"情绪场",
   不是地图。传递平静、干净、有呼吸感。
2. **焦点极度集中(铁律)**:全场唯一高饱和/高细节/暖色的东西 = 用户自己的真树 + 脚下草岛。
   世界很淡,只有"你的真实那一小块"是实的。这在无声讲 North Star——现实的那块是唯一"真"的。
   **保留为铁律:任何时候只有真实资产是视觉主角。**
3. **暖白毛玻璃卡片**:与 onboarding 同族,半透明圆角浮于背景,承载所有信息,不用硬边框。
4. **细衬线大标题 + 手绘水彩贴纸图标**:标题优雅细衬线(吃现有 token);功能图标手绘、暖、拙。
   **衬线的雅 × 手绘的拙 = 品牌气质。**
5. **绿 + 暖白 + 一点金**:主绿 `#4C8C4A`/深绿 `#2F5E3A`,暖白底 `#F7F4EC`,Seeds 用暖金/琥珀
   点缀区分。品牌色是绿,金只在 Seeds 上。

**代码 vs 美术分工(重要,沿用 Step 1"代码建方向、留插画槽"原则):**
- 树 / 岛 / 背景是**预先画好/渲染好的插画资源**,代码不生成它们,只做卡片、文字、图标、
  布局与合成。
- 参考渲染图里的"活的树"必须靠美术资源实现;CC 能还原的是结构、卡片氛围、布局与合成逻辑。

## 二、核心澄清:My World 的树 ≠ 农民照片本身

分两层,永不混淆:
- **My World 岛上的树 = 风格化的"成长阶段插画"**(你的树的卡通化身),按成长阶段换图。
- **农民发的真实照片 = 证据**,放在**更新卡片 / 树详情页**,不贴进梦境场景。
  → 原因:照片尺寸/角度/光线不可控,贴进场景会脏、拼不起来。**照片进详情,插画进世界。**

**结果:风格统一,内容千人千面。** 所有用户共用同一套成长阶段插画(每物种约 4–5 阶段),
但"你领养了哪几棵、各自到哪个阶段、岛多大"是你独有的组合。不是所有人首页长一样。

## 三、动态岛 / 多树架构(owner 预想:岛随领养生长、树间可切换观察)

**采用方案 A —— 槽位式合成(V1 可行)。** 放弃方案 B(程序化连续生成)——那是 V2+
(与精确 GPS/AR/AI 同档)的野心,V1 做会拖垮进度且树少时看不出差别。

方案 A 定义:
- 岛 = 底图 + 若干**预留树位(slots)**。每领养一棵,往下一个空槽贴一棵树插画
  (按物种 + 当前成长阶段选对应图)。
- **岛"变大" = 分档背景**:按已领养棵数命中阈值换更大的岛底图(0 / 1–3 / 4–8 / …,
  阈值待定)。分档跳变而非连续变形,用户几乎无感,视觉完全成立。
- **树间切换 = 点某棵树进详情页**观察其状态与真实更新。
- 美术量可控:几张岛底图 + 每物种几个成长阶段树 PNG;代码做前端合成(按槽位坐标叠图)。

**依赖:** 需要先有"领养流程"和"成长阶段"数据模型才能拼装。故此模块属 GROVE/My World
动态化那轮,不属 onboarding。

## 四、成长阶段模型(owner 已敲定,四条)

树在 My World 里显示哪张阶段插画,由"成长阶段"决定。阶段推进有两种来源,**视觉与语义
必须可区分**——否则用户分不清真假,"这是真的"这一唯一护城河被自我稀释。

1. **阶段插画 ≠ 农民照片本身**(见第二节)。共用阶段插画;照片进详情。

2. **主驱动 = 农民里程碑(真实推进)**:农民发更新时打 milestone(如 发芽/长叶/开花/结果)→
   树进入新阶段。视觉是实的、亮的、正常树插画,配真实更新文案("农民说:它长出新叶了")。
   → 代价:农民不发里程碑,树在世界里就不长——再次印证"农民端是真正瓶颈"。

3. **兜底 = 系统按时间/领养时长推进,但明确标注"等待农民确认"(临时推进)**:
   农民长时间沉默时,系统让树"看起来长了一点",但**必须标注为未确认状态**——
   例如树插画带半透明/柔光/虚化处理,挂诚实文案:"你的树在生长中,等待农民确认更新 🌱"。
   **核心原则:系统可让树"看起来在长",但绝不能声称"农民说它长了"。**
   真实来源配真实措辞,系统兜底配"等待确认"措辞,用户永远知道在看哪一种。

4. **两个参数(owner 已定):**
   - **触发兜底的"沉默时长"= 可配置占位常量,不写死天数。** 等有真实农民节奏数据再调。
     倾向保守:领养后先走"诚实等待桥"(见第五节),兜底不宜太快,太快等于纵容农民摆烂。
   - **兜底有天花板:** 系统最多把树推到某个早期阶段(如 发芽/长叶)。
     **开花、结果等关键里程碑只能由农民真实里程碑解锁。** 杜绝"系统凭空结的果"。

## 五、诚实等待桥(产品最高优先级,与成长模型咬合)

领养到第一张真实农民照片之间,必须有**诚实的等待状态**,不是假 XP、不是假成长:
- 领养刚完成 → 树处于"刚安家/生长中",配文案如"你的树刚安家,农民很快会带来第一张照片"。
- 首张真实照片 = "这是真的"的唯一证据,也是 churn 高发区 → 到达速度与可靠性是最高优先级,
  真正瓶颈在农民端(发更新要比发朋友圈还简单)。
- 兜底推进在首照到来前尤其克制,避免用"系统假成长"替代"真实首照"这件唯一要紧的事。
